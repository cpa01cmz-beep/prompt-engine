Follow-up to `audit-2026-10-20.md` (phase 2). Verification note: upstream AI errors should be 502, not 500. Changes are code-only.

## Changes
- `src/worker/routes/ai.ts` and `src/worker/routes/search.ts`: every route `catch` now maps upstream failures (fetch throws, non-ok responses) to a generic `502 { ok: false, error: "Upstream AI error" }`. The thrown error (which embeds the upstream error body/status from `chatCompletion`) is logged server-side only and never reflected to the client.
- Shared helper `src/worker/lib/outboundError.ts`: `mapOutboundError(c, cause)` logs the cause with `console.error` server-side and returns the generic 502 response; all 12 route catch blocks call it.
- Tests: new `tests/unit/outboundError.test.ts` (4 tests, mocked `fetch` via `vi.stubGlobal`): generic 502 mapping, cause logged but never surfaced in the response body, non-ok upstream response for `/api/ai/generate-prompt`, rejecting upstream for `/api/search/web`.
