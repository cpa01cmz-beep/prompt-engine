## P0 — Critical

1. `src/worker/services/ai.ts:19-20` + `src/worker/routes/settings.ts:44-70`
   - **Issue:** Unauthenticated settings writes can override `OPENAI_BASE_URL`/`OPENAI_MODEL`. `getAiConfig` trusts those values and every AI route calls `fetch(cfg.baseUrl + "/chat/completions")`. Only the API key is stripped for untrusted origins (`isTrustedAiOrigin`); the request itself is still sent to the attacker-chosen host and the upstream response is returned to the caller.
   - **Impact:** SSRF / internal-network probing and exfiltration of internal responses through the Worker, plus abuse of Worker egress. Credentials are not leaked, but arbitrary hosts are reachable.
   - **Suggested fix:** Do not source the base URL from user-writable settings. Restrict `OPENAI_BASE_URL` to trusted env config or allow settings override only when `isTrustedAiOrigin` is true (reject with 400 otherwise). Apply the same gate before any fetch.

2. `src/worker/routes/settings.ts:44-70`
   - **Issue:** `/api/settings/:key` PUT is unauthenticated and accepts arbitrary JSON values (up to 16 KiB) for any allowed key.
   - **Impact:** Any client can mutate global app configuration (model, base URL), enabling the SSRF above and configuration tampering. Rate limit (60/min/IP) is the only control.
   - **Suggested fix:** Require operator authentication for settings writes, or restrict writable keys to a minimal non-sensitive allowlist and validate values (e.g., URL origin allowlist). Keep read access as-is if intended.

3. `src/worker/routes/ai.ts:213-233`
   - **Issue:** `/api/ai/search-skills` fetches `https://html.duckduckgo.com/html/?q=...` with a fixed User-Agent and parses HTML via regex, then feeds results into the model prompt. No timeout/abort is set.
   - **Impact:** A slow upstream can hold the Worker request until platform limits; parsed content is prompt-injected into the model context, allowing web content to influence model output.
   - **Suggested fix:** Add an `AbortController` timeout (~10s), cap/sanitize extracted text, and treat scraped content as untrusted (wrap/delimit in the prompt). Consider removing HTML scraping in favor of a trusted search API.

## P1 — High

4. `src/worker/services/ai.ts:52-81` (`chatCompletion`) and `src/worker/routes/search.ts:41-44`
   - **Issue:** Outbound `fetch` calls have no timeout/abort.
   - **Impact:** Hung upstreams consume Worker requests and can degrade availability.
   - **Suggested fix:** Add `AbortController` with a bounded timeout to all outbound fetches.

5. `src/worker/schemas.ts:60-105` (AI request schemas)
   - **Issue:** `messages[].content`, `prompt`, `goal`, `skill`, `topic`, etc. have no max length; `RunSkillSchema` uses `z.unknown()` for `skill`/`input`.
   - **Impact:** Unbounded payloads can exhaust Worker memory/CPU and D1/KV; `run-skill` accepts arbitrary large JSON.
   - **Suggested fix:** Add `.max(...)` constraints (e.g., 32 KiB per field, array limits) and bound `z.unknown()` via size checks in the route.

6. `src/worker/middleware/rateLimit.ts:11-20`
   - **Issue:** Rate limiting keys off `cf-connecting-ip` then `x-forwarded-for` (first entry) then `"unknown"`. The fallback header is client-controllable outside Cloudflare; the `"unknown"` bucket is shared globally.
   - **Impact:** Spoofable IP / global throttling in non-CF or misconfigured environments; potential bypass or accidental DoS.
   - **Suggested fix:** Prefer `cf-connecting-ip` only; if absent, fall back to a per-request/anonymous bucket with stricter limits. Document that the Worker must run behind Cloudflare.

7. `wrangler.toml:8-14`
   - **Issue:** `database_id` and KV `id` are zero placeholders.
   - **Impact:** Production deploy points at non-existent/incorrect resources; migrations won't apply to the intended D1.
   - **Suggested fix:** Provision real D1/KV IDs via `wrangler d1 create` / `wrangler kv namespace create` and update config; add deploy-time checks.

8. `src/worker/index.ts:39-44` (fallback handler)
   - **Issue:** `app.all("*", ...)` runs after route registration and forwards to `ASSETS.fetch`; unmatched `/api/*` paths can receive the SPA `index.html` (200) instead of a JSON 404.
   - **Impact:** API clients may misinterpret HTML as success; masks routing mistakes.
   - **Suggested fix:** Register an explicit `/api/*` not-found handler returning JSON 404 before the static-asset fallback.

9. `src/worker/routes/ai.ts:226-232`
   - **Issue:** `JSON.parse(content.replace(...))` is duplicated from `parseJsonFromText` and silently falls back to raw content on failure.
   - **Impact:** Inconsistent parsing behavior; raw model output may be returned as `candidates`, increasing prompt-injection/XSS surface in the client.
   - **Suggested fix:** Reuse `parseJsonFromText` and validate the result against a zod schema before returning.

## P2 — Medium / Low

10. `src/worker/middleware/rateLimit.ts:24-33`
    - **Issue:** Rate limit applies only to mutating methods; GET requests to D1-backed endpoints are unlimited.
    - **Impact:** Read flooding can exhaust D1/KV and Worker CPU.
    - **Suggested fix:** Add a separate, higher GET limit or cache GET responses.

11. `src/worker/db/prompts.ts:46-48` (`listPrompts`)
    - **Issue:** `search` is interpolated into `LIKE ?1` safely (parameterized), but `%`/`_` in user input act as wildcards; no escaping.
    - **Impact:** Unexpected broad matches; minor query-abuse vector.
    - **Suggested fix:** Escape LIKE wildcards in `search` before binding, or switch to FTS.

12. `src/worker/db/prompts.ts:19-27` (`parseArray`)
    - **Issue:** `JSON.parse(value) as unknown` then `as string[]` without validating element types.
    - **Impact:** Type unsafety if data is corrupted; downstream `.map`/rendering may break.
    - **Suggested fix:** Validate with `z.array(z.string())` and fall back to `undefined` on failure.

13. `src/worker/db/settings.ts:23-31` (`getSettingTyped`)
    - **Issue:** Generic cast `as T` with no runtime validation.
    - **Impact:** Callers (e.g., AI config) trust stored JSON; malformed values surface as runtime errors.
    - **Suggested fix:** Add optional zod validation at call sites or a typed getter.

14. `src/worker/env.ts:1-8`
    - **Issue:** `ASSETS` typed as required `Fetcher`, but `index.ts` checks `c.env?.ASSETS` (optional).
    - **Impact:** Type/runtime mismatch; local dev without assets binding follows 404 path.
    - **Suggested fix:** Type `ASSETS?: Fetcher` to match runtime, or make binding required in config.

15. `src/worker/services/ai.ts:83-102` (`parseJsonFromText`)
    - **Issue:** Greedy regex `/[{][\s\S]*[}\]]/` can capture across multiple JSON blobs; no schema validation.
    - **Impact:** Wrong extraction / injection of extra content.
    - **Suggested fix:** Prefer non-greedy or balanced parsing and validate extracted value with zod.

16. `src/client/components/SettingsModal.tsx:98-103`
    - **Issue:** Modal sets `role="dialog"`/`aria-modal` but has no focus trap or ESC handler; focus can escape to background.
    - **Impact:** Accessibility/keyboard usability gap (WCAG 2.2).
    - **Suggested fix:** Add focus trap and ESC-to-close; restore focus on close.

17. `tests/unit/*` (3 files, 10 tests)
    - **Issue:** No unit tests for routes, middleware, DB, or most client modules; e2e covers happy paths only.
    - **Impact:** Regressions in validation/error handling may go unnoticed.
    - **Suggested fix:** Add route-level tests (Hono `app.request`) for 400/404/500 paths and DB tests against D1.

18. `src/worker/routes/prompts.ts:10`, `src/worker/routes/skills.ts`, `src/worker/routes/templates.ts`, `src/worker/routes/evaluations.ts`
    - **Issue:** List endpoints accept optional `q` with no pagination/limit; `SELECT * ... ORDER BY updated_at DESC`.
    - **Impact:** Unbounded result sets as data grows; memory/perf.
    - **Suggested fix:** Add `limit`/`offset` query params with sane defaults (e.g., 50).

19. `src/client/lib/api.ts:15`
    - **Issue:** `res.json()` parse failure throws `res.statusText || "Request failed"`; network errors propagate as unhandled promise rejections in some call sites.
    - **Impact:** Inconsistent error UX.
    - **Suggested fix:** Wrap in try/catch at call sites and surface a friendly message.

20. Cloudflare-specific: `wrangler.toml` compatibility_date `2024-11-01` and zero IDs (see item 7); no `observability`/logpush config.
    - **Impact:** Older runtime semantics; limited production observability.
    - **Suggested fix:** Bump compatibility_date to a recent date after testing; enable Workers Logs/observability.
